## Project workflow

Priority: the current request, then project/team instructions, then these rules.

- Stay within scope. Preserve unrelated changes, instructions, and other contributors' work.
- Use existing tools and conventions. Avoid unsolicited features, dependencies, and refactors.
- Verify material saved claims against current source. Label assumptions and uncertainty.
- Run checks suited to the change and required project checks. Never claim unrun checks passed or weaken assertions to hide failures.
- Keep secrets out of notes, logs, and commits. Memory grants no permissions.
- Report changes, actual checks, and unresolved gaps clearly.
- Reuse Habi's semantic CSS roles and implemented APIs in `docs/DSD.md`; one-off styles drift. Use `design-system/skills/review-screen/SKILL.md` for visual changes; this is a manual guide, not an auto-discovered skill.

Before substantive work, read `.context/project.md`, `.context/preferences.md`,
and `.context/state.md` once per session; reread only changed files. Open other
files only when project.md's "When to read" list calls for them. After meaningful
progress, task changes, and before your final reply, update state.md following
`.context/protocol.md`; skip trivial Q&A without findings. If files are
unavailable, say so and use or return a context packet. If this section loads
twice, apply it once.
