# Habi exact-reference screen review

1. Read [DSD](../../../docs/DSD.md), [canonical CSS](../../../public/assets/css/app.css) and the changed templates. The [published UI and design system](https://fit-igloo-66636772.figma.site/) is authoritative, not the previous implementation. Inspect its Application Examples without treating the documentation sidebar, preview frame, viewport picker or Demo state control as storefront UI.
2. Run the [README quickstart](../../../README.md). Compare source and actual app at native 1440, 768 and 360 px widths: exact font files/weights, heading wraps, container padding, vertical rhythm, component anatomy, backgrounds, artwork and selected states. A palette match is insufficient. Keep real data differences separate from visual drift; never claim pixel identity without a comparison.
3. On discovery: check the mosaic hero, process diagrams, four material tabs, asymmetric featured editorial and dark CTA/footer. Exercise Skip introduction, material mouse/keyboard selection, and mobile menu focus/Esc/return. Verify meaningful no-JS fallback instead of an inaccessible hidden navigation.
4. On catalog: exercise native/progressive search, category, featured/newest/price sorting, Hide sold-out bags, eight-item pagination, retained query values and empty/reset state. Inspect the reference card image/name/material/price/stock-chip structure and separate links from actions. Never seed fake cart counts or successes to resemble sample state.
5. On product: inspect Images/3D, current gallery assets, open materials/dimensions/provenance sections and purchase panel. Exercise actual Three.js loading, retry, WebGL image fallback, rotate/reset/pause and Peek inside / Back outside on all four shapes. Check configured lining/pockets/dividers, actual flap opening only where modeled, repeated/rapid reversals, inside orbit, current-mode reset, immediate reduced-motion/keyboard changes, and narrow fullscreen focus containment/Esc/return. Preserve real dimensions/stock; exercise enabled M4 Add to bag and disabled sold-out actions. Do not substitute the conceptual CSS viewer or invent interior images.
6. On bag: compare drawer and full-page line/summary anatomy with the published Cart example at 1440, 768 and 360 px. Exercise listing/detail add, bounded steppers, remove, native no-JS forms, server badge after navigation, reload persistence, shipping estimate and empty state. Reduce isolated fixture stock and verify persistent explanatory corrections, then zero stock and verify removal/rejection. Check drawer Tab/Shift+Tab containment, Esc/focus return and menu handoff; never port the showcase's stock-change control. Proceed to checkout must open the real guest shipping flow.
7. Verify visible focus, named icon controls, text+icon statuses, published control sizing, contrast of actual text/UI pairs, and no unintended horizontal scroll at 360 px. Light theme only. Check local font/artwork loading and licenses. Supplied reference photographs remain unpublished.
8. On checkout: compare native 1440/768/360 px Shipping, Payment, Review and Confirmation against the published examples. Complete a keyboard-only and no-JS purchase with fictional data. Check inline shipping/card errors, all three test-card outcomes, processing status/reduced motion, retained shipping/bag on declines, server-side prerequisite enforcement and simulation notices. Use isolated stock to exercise concurrent last-item placement, rollback, price/stock correction and same-key retries. Confirmation must use actual snapshots and be inaccessible from another session; never capture PAN/CVC in saved evidence.
9. Report observed differences by screen/state, expected versus actual, severity, visual/source anchor and smallest correction. Distinguish data/milestone constraints, unrun checks and real visual mismatches. Do not approve a deliberate visual deviation merely because the old UI behaved that way.
